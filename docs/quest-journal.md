# Журнал заданий Stellar Croak

Документ описывает игровой дизайн и техническую реализацию журнала заданий:
типы и сферы, полный каталог, модель прогресса, сохранение, награды и UI.

Журнал — мягкий гид по колонии. Он не заменяет туториал и не запирает контент:
игрок может строить, кормить и летать в любом порядке, а журнал подсказывает
следующий осмысленный шаг и платит за него. Награда не начисляется сама —
выполненное задание ждёт в журнале, пока игрок не нажмёт «Забрать награду».

Главные принципы:

- **каталог — единственный источник правды.** Названия, цели, награды и цепочки
  лежат в `src/backend/quests-manager/quests-list.ts`; UI и сохранение ничего не
  знают о конкретных заданиях;
- **прогресс считается из `GameState`.** Комнаты, ресурсы, жабы и секторы не
  дублируются в журнале, поэтому прогресс не может разойтись с игрой;
- **события — только для того, что нельзя вывести из состояния.** Кормление,
  покупка корма, лутбокс и болезни учитываются накопительными счётчиками;
- **цепочка открывается после выполнения, а не после получения награды.**
  Иначе игрок с незабранным подарком застрял бы в середине цепочки;
- **получение награды идемпотентно.** Повторный клик и двойной тап не
  задваивают ресурсы.

## A. Типы заданий

| Тип | Название в UI | Штук | Темп | Как открывается | Роль |
| --- | --- | ---: | --- | --- | --- |
| `quick` | ⚡ Быстрое | 16 | 2–15 минут | сразу, после предыдущего задания или по событию | первый цикл: корм, капсула, первые постройки, лутбокс, лечение |
| `medium` | ⏳ Среднее | 13 | 30 минут – несколько часов | цепочка из 2–4 шагов | четыре параллельные ветки развития колонии |
| `long` | 🗺️ Долгое | 4 | дни | последовательная магистраль | сквозной маршрут через весь КОНТУР |

Всего **33 задания**. Суммарная награда за полное прохождение — **700 🔷,
785 💎 и 44 📦**. Награды быстрых заданий в основном закрывают ранние расходы
на корм и первые постройки; средние дают лутбоксы и Кваксов на лабораторию и
селекцию; магистраль — главный источник астро-кваксов и больших упаковок
лутбоксов.

Магистраль состоит из четырёх последовательных заданий. В журнале она всегда
показана отдельным блоком «Магистраль КОНТУРа»: даже закрытые шаги видны, чтобы
игрок понимал, куда ведёт путь. Открытие шага — по выполнению предыдущего.

Цепочки специально начинаются с разных быстрых заданий (`q06`, `q05`, `q11`,
`q10`), поэтому после первых пятнадцати минут у игрока обычно открыто сразу
несколько средних веток. Внутри ветки шаги в основном идут строго по порядку;
`m07` и `m10` — боковые ответвления от быстрых `q15` и `q16`, поэтому могут
открыться раньше последнего шага своей секции.

| Цепочка | Задания | Тема |
| --- | --- | --- |
| Экономика и снабжение (`supply`) | `m01` → `m02`, `m03` | капитал, склад, астро-валюта |
| Колониальный уклад (`colony`) | `m04` → `m05` → `m06` → `m07` | жильё, энергия, лаборатория, профилактика |
| Селекция и коллекции (`selection`) | `m08` → `m09` → `m13`, боковая `m10` | племенная линия, виды, экспедиционный резерв, архив |
| Периметр (`perimeter`) | `m11` → `m12` | глубина и открытие секторов |

Формально `m02` и `m03` — две ветки после общего `m01`; в каталоге они идут
подряд, а UI показывает обе в одной секции цепочки.

`m13-expedition-reserve` требует закрыть пять экспедиционных ролей взрослыми
жабами из селекции или коллайдера (у каждой есть `parents`):

| Роль | Характеристика | Порог |
| --- | --- | --- |
| Оператор | силы + качество | 150 ⚡ + 10 |
| Скаут | скорость | 1.2 |
| Щитоносец | размер | 18 |
| Ремонтник | плодовитость | 1.2 |
| Повар | аппетит | 1.2 |

Одна жаба может закрыть несколько ролей сразу, если проходит их пороги.
Метрика считает именно число покрытых ролей, а не число жаб: универсал со всеми
статами закрывает все `5/5` в одиночку. Дикие жабы и жабы из лутбоксов с теми
же цифрами не считаются: задание именно про выведенную линию. Вместе с `m13`
работает общее ускорение генетики:
положительный прирост характеристик в репродукторе и коллайдере теперь идёт ×2
(`GENETIC_PROGRESS_MULTIPLIER`), включая качество, бонус за число родителей и
удачные мутации. Штрафы и случайные ухудшения не усиливаются.

### D2. Сохранение

Ключ: **`quest_journal`**. Он отдельный от `Game_State6`: журнал не участвует в
облачном синке игры и не раздувает основной сейв.

```json
{
  "version": 1,
  "activated": ["q01-first-sector", "q04-first-feed", "l01-first-contour"],
  "completed": [],
  "claimed": [],
  "counters": { "toad_fed": 3, "food_bought": 10 },
  "activatedAt": { "q01-first-sector": 1760000000000 },
  "completedAt": {},
  "claimedAt": {},
  "firstSeenAt": 1760000000000,
  "lastSeenAt": 1760000000000,
  "sessions": 1
}
```

| Поле | Смысл |
| --- | --- |
| `activated` | задания, чьи триггеры уже сработали (видны как активные) |
| `completed` | цель достигнута, награда ещё не забрана (статус `ready`) |
| `claimed` | награда забрана, задание в архиве |
| `counters` | накопительные события: `toad_fed`, `food_bought`, `lootbox_opened`, `toad_cured`, `disease_outbreak` |
| `activatedAt` / `completedAt` / `claimedAt` | метки времени для архива и будущей аналитики |
| `firstSeenAt` / `lastSeenAt` / `sessions` | статистика журнала и задел для заданий «заходите N раз» |

Нормализация при чтении защищает от битого JSON, дублей в списках, чужих
ключей счётчиков и отрицательных значений. `claimed` всегда является
подмножеством `completed`: повреждённая запись не даст забрать награду за
невыполненное задание.

### D3. Триггеры

| Тип | Условие | Используется сейчас |
| --- | --- | --- |
| `always` | доступно сразу | три стартовых задания |
| `chain` | предыдущее задание есть в `completed` | 12 быстрых (кроме стартовых и событийных), все средние и `l02`–`l04` |
| `metric` | абсолютная метрика `>= value` | поддержано, в каталоге пока не используется |
| `event` | счётчик события `>= value` (по умолчанию 1) | `q07`, `q08` |
| `time` | прошло `days` от `createdAt` и/или `minutes` с запуска приложения | поддержано, пока не используется |
| `all` | все вложенные триггеры истинны | поддержано, пока не используется |

`time.minutes` считается от `QUEST_SESSION_STARTED_AT`, то есть от загрузки
модуля, а не от открытия модалки. Для длинных пауз между сессиями есть
`playDays` на основе `createdAt` сейва.

### D4. Статусы и прогресс

```text
locked ──триггер──▶ active ──цель──▶ ready ──«Забрать»──▶ claimed
```

| Статус | Что видит игрок | Что можно делать |
| --- | --- | --- |
| `locked` | подсказку, после какого задания откроется | ничего |
| `active` | описание, подпись и полосу прогресса | ждать/играть |
| `ready` | 100 % и кнопку «Забрать награду» | забрать |
| `claimed` | карточку в архиве и метку «получено» | только смотреть |

Статус не откатывается: если цель задания была достигнута, оно останется
выполненным, даже если игрок потратит ресурсы. Поэтому цели на «накопить» и
«построить» проверяются в момент выполнения, а не постоянно.

Прогресс всегда ограничен сверху (`min(value, target)`), поэтому перевыполнение
не ломает полосу. Для бинарных целей можно задать отдельную `progressMetric` и
`progressTarget` — так сделано у `l04`.

### D5. Метрики

Движок собирает `QuestMetrics` за один проход по `GameState`:

| Группа | Метрики | Источник |
| --- | --- | --- |
| Жабы | `toads`, `adultToads`, `toadSpecies`, `generation2Plus`, `toadsWithParents`, `expeditionReserveRoles`, `sickToads` | `state.toads` |
| Колония | `rooms`, `aviaryRooms`, `breedingRooms`, `colliderRooms`, `scoutRooms`, `shopRooms`, `hospitalRooms`, `powerRooms`, `storageRooms` | `state.colony.rooms` |
| Ресурсы | `tokens`, `astroQuax`, `food`, `lootboxes`, `geneDust`, `contourPass` | `state.user` |
| Разведка | `completedSectors`, `unlockedSectors`, `lastSectorCompleted`, `completedExpeditions`, `bestDepth` | `expeditionStats` |
| Время | `playDays`, `sessions` | `createdAt`, журнал |
| События | `fedToads`, `foodBought`, `lootboxOpened`, `curedToads`, `diseaseOutbreaks` | счётчики журнала |

Метрики, выведенные из `GameState`, не сохраняются в журнале. Счётчики событий
сохраняются, потому что восстановить их из текущего состояния нельзя: факт
кормления или лечения уже не виден в сейве.

`expeditionReserveRoles` считается через `countExpeditionReserveRoles` из
`utils/expedition-config.ts`: у взрослых жаб с непустым `parents` проверяются
пороги `EXPEDITION_RESERVE_REQUIREMENTS` (силы и качество, скорость, размер,
плодовитость, аппетит), после чего роли объединяются в одно множество. Одна
жаба может закрыть несколько ролей сразу. Текущие HP, сытость и место жабы не
учитываются — это постоянная характеристика линии, а не состояние в моменте.

### D6. Пересчёт журнала

`refreshQuestJournal()` — центральная функция; её вызывают снимок, события и
получение награды.

1. `registerQuestJournalSession()` один раз за загрузку модуля увеличивает
   `sessions`, обновляет `lastSeenAt` и ставит `firstSeenAt`.
2. `getQuestMetrics()` читает `GameState` и счётчики.
3. Цикл до `QUESTS.length + 1`:
   - все задания с невыполненным триггером проверяются на активацию;
   - все активные задания проверяются на достижение цели.
4. Если были изменения, состояние пишется одним `updateQuestJournalState`, и
   рассылается `questJournalUpdated` с массивами `activated` / `completed`.
5. `getQuestJournalSnapshot()` превращает состояние в `entries`, `ready`,
   `active`, `claimed` и `counts`.

Повторные проходы нужны для цепочек в одном тике: например, игрок строит
Торговую капсулу, `q01` выполняется, `q02` открывается, и всё это происходит до
возврата из функции. Ограничение числом заданий исключает бесконечный цикл.

`recordQuestEvent(event, amount)` сначала пишет счётчик, затем вызывает
`refreshQuestJournal()`. Поэтому событийное задание активируется уже с новым
значением и может стать `ready` в том же проходе (так работает `q07` после
первого лутбокса).

### D7. События и их источники

| Событие | Где вызывается | Что считается |
| --- | --- | --- |
| `toad_fed` | `ToadContext.tsx` → `handleFeedToads` | число реально накормленных жаб; жабы в походе и при нехватке корма не считаются |
| `toad_fed` | `utils/auto-feeder.ts` → `feedHungryToads` | число жаб, которых накормила автокормушка; это тот же прогресс, что и ручное кормление |
| `food_bought` | `ShopMenu/BuyTab/use-shop.ts` | количество корма в купленной упаковке (10 или 100), а не число кликов |
| `lootbox_opened` | `StorageModal/index.tsx` | один израсходованный лутбокс; фиксируется после списания, до выбора биопода |
| `disease_outbreak` | `utils/disease-manager.ts` → `infectToad` | только реальное заражение, повторный вызов для больной жабы не считается |
| `toad_cured` | `utils/disease-manager.ts` → `cureToad` | только переход «больна → здорова», клик по здоровой жабе не двигает прогресс |

Событие — это не «лог действий», а счётчик для заданий. Если новый источник
кормления или лечения появится в коде, он должен вызвать `recordQuestEvent` с
тем же смыслом, иначе задание не заметит действие.

### D8. Награды

| Шаг | Что происходит |
| --- | --- |
| 1 | `claimQuestReward` находит задание по id и вызывает `refreshQuestJournal` |
| 2 | проверяет `claimed` и `completed`; неизвестное/невыполненное/уже забранное возвращает `{ success: false }` |
| 3 | читает актуальный `GameState`, готовит `storage` с лутбоксами |
| 4 | `updateUser` начисляет Кваксов, астро-кваксов и лутбоксы |
| 5 | только после начисления добавляет id в `claimed` и ставит `claimedAt` |
| 6 | рассылает `questJournalUpdated`; UI показывает уведомление и звук |

Порядок «сначала награда, потом отметка» выбран осознанно: если запись журнала
не удастся, игрок увидит задание снова, но не потеряет ресурсы. Двойной клик
безопасен: второй вызов увидит `claimed` и вернёт отказ.

`claimAllQuestRewards()` берёт текущий `ready` и вызывает `claimQuestReward`
последовательно, повторяя проход, пока не останется готовых наград. Это важно:
награда за одно задание может изменить ресурсы и тем самым закрыть следующее —
как `q06` после наград `q02`–`q04`. Кнопка «Забрать всё» показывает количество
успешно забранных наград, включая открывшиеся во время получения.

### D9. UI и поток данных

- **Кнопка HUD** (`QuestJournalButton`) стоит слева от меню колонии, показывает
  иконку журнала и янтарный бейдж с числом `ready` (максимум «9+»). Бейдж
  реактивен: хук подписан на `gameStateUpdated` и `questJournalUpdated`.
- **Модалка** (`QuestJournalModal`) открывается через `useModal` и состоит из:
  - трёх статистических плиток: к получению / в работе / закрыто из 33;
  - кнопки «Забрать всё», если есть `ready`;
  - трёх вкладок.
- **В работе**: сначала блок «Награды ждут», затем «В работе». Карточка
  показывает сферу, тип, статус, описание, прогресс и награду; у `ready` есть
  кнопка получения.
- **Цепочки**: четыре секции `QUEST_CHAINS` с прогрессом «закрыто / всего» и
  отдельная секция «Магистраль КОНТУРа». Закрытые карточки не скрываются, а
  показывают подсказку триггера.
- **Архив**: `claimed`, отсортированные по `claimedAt` от новых к старым.
- Данные в компоненты приходят только из снимка; порогов и названий заданий в
  JSX нет. Новое задание появляется в UI автоматически.

Хук не использует таймеров: снимок пересчитывается при записи игры и при
событиях журнала. Это дешевле polling и не создаёт расхождений.

### D10. Граничные случаи

| Ситуация | Поведение |
| --- | --- |
| Игрок выполнил цель, но не забрал награду | задание остаётся `ready`; следующее в цепочке уже открыто |
| Игрок закрыл игру между начислением и записью `claimed` | награда не потеряна; при следующем открытии задание снова `ready` |
| Повторный клик / двойной тап | второй вызов возвращает «Награда уже получена», ресурсы не меняются |
| Старый сейв без журнала | создаётся чистый журнал; стартовые задания активируются, уже выполненные цели сразу становятся `ready` |
| Битый JSON журнала | чтение отдаёт чистый журнал, игра не падает |
| Неизвестный id задания | `claimQuestReward` возвращает «Задание не найдено» |
| `recordQuestEvent` с 0, отрицательным или `NaN` | счётчик не меняется |
| Событие случилось до первого открытия журнала | счётчик записывается, задание активируется при следующем пересчёте |
| Достигнута цель `l04`, но `l03` ещё не выполнена | `l04` останется `locked` до выполнения `l03`; после — сразу `ready` |
| Цепочка `m01` завершена, награда не забрана | `m02` и `m03` уже открыты |

### D11. Как добавить задание

1. Добавить `QuestDef` в `quests-list.ts` (быстрый/средний/долгий хелпер).
2. Выбрать триггер: `always`, `chain` от существующего id, `metric` или
   `event`. Для нового события добавить его в `QuestEvent` и `EVENT_NAMES`,
   затем вызвать `recordQuestEvent` в источнике действия.
3. Указать цель и `label`; при необходимости — `progressMetric` /
   `progressTarget`.
4. Для среднего задания добавить id в `QUEST_CHAINS[].taskIds` и `chainId`.
5. Проверить: `node tmp-verify-quest-journal.mjs`, `npm run build`.
   UI и `storage.ts` править не нужно.

`priority` зарезервирован для будущей сортировки; сейчас снимок идёт в порядке
каталога. `starter` — семантический флаг для стартовых заданий, активация
которых идёт через `always`.

### D12. Проверка

```bash
node tmp-verify-quest-journal.mjs   # или npm run verify:quest-journal
npm run build
```

Скрипт бандлит реальные модули через esbuild и проверяет каталог, стартовые
задания, цепочки, награды, счётчики событий, сохранение и защиту от повторного
получения. TypeScript-проверка всего проекта (`npx tsc --noEmit`) содержит
исторические ошибки в старых модалках и Canvas; файлы журнала в этот список не
входят.
